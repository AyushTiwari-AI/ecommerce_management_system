HOW TO USE THIS FILE
1. Open this TXT file in Notepad.
2. Copy the OUTPUT section you need for your practical record.
3. Each output is shown in a clean table layout, followed by a simple reason.
4. These are EXPECTED/sample outputs based on the sample records in ecommerce_management.sql.
   Your MySQL Workbench output can differ slightly in formatting and dates.

IMPORTANT CORRECTION ABOUT THE SQL SCRIPT
The DELETE query for old cancelled orders can fail because Order_Items and Payments contain
foreign-key references to that order, and the tables do not use ON DELETE CASCADE.
MySQL may show error 1451 (cannot delete/update parent row). If this happens, the cancelled
order remains in Orders. The outputs below assume the original sample data remains, unless
the section says otherwise. Date-based outputs use 23-10-2026 as the example run date.

2.3 DELETE OLD CANCELLED ORDERS

EXPECTED OUTPUT IF FOREIGN-KEY ERROR OCCURS
ERROR 1451: Cannot delete or update a parent row: a foreign key constraint fails.

REASON
The order is referenced by Order_Items and Payments. MySQL prevents deleting a parent order
while child rows still reference it. To make this DELETE succeed, delete/update the related
child rows first or define an appropriate ON DELETE rule. Do not delete child records unless
that is intended for your practical.

==============================================================================
12. WINDOW FUNCTIONS
==============================================================================

12.1 RANK CUSTOMERS BY TOTAL SPENDING

OUTPUT COLUMNS
customer_id | name | total_spending | spending_rank

REASON
The CTE first calculates each customer's total non-cancelled spending. RANK assigns a position
from highest to lowest spending while keeping each customer in a separate row. Equal totals
receive the same rank.

12.2 RUNNING TOTAL OF REVENUE PER MONTH

OUTPUT COLUMNS
order_month | monthly_revenue | running_total_revenue

REASON
The query first calculates revenue per month. SUM(...) OVER (ORDER BY order_month) then adds
each month's revenue to the previous months, producing a cumulative running total.

12.3 RUNNING TOTAL OF ORDER AMOUNTS

OUTPUT COLUMNS
order_id | order_date | total_amount | running_order_total

REASON
SUM(total_amount) OVER (ORDER BY order_date, order_id) calculates a running total in date order.
Unlike GROUP BY, a window function keeps one output row per order.
